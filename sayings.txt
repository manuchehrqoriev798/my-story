# Part 3

One thing I realized after using AI tools heavily for coding is that the workflow matters more than the model itself.

A lot of people argue about which model is the best: Claude, GPT, Gemini, etc. But in reality, productivity comes from using the right tools together, not just picking the “best” model.

A decent site to see which models are currently strong:
https://artificialanalysis.ai/leaderboards/models

Benchmarks are not perfect (and often a bit biased), but they give a rough idea of what's strong right now.
But honestly, don't spend too much time obsessing over leaderboards. What matters more is how you use the tools in practice.





My current AI coding setup

Instead of relying on a single IDE or tool, I usually switch between several depending on the task.

Cursor: great for normal AI-assisted coding and debugging.

Windsurf: good when working with larger contexts or structured coding workflows.

Zed + Codex extension: extremely fast editor, nice for quick edits or lightweight generation.

Antigravity: more agent-like. It can run browser sessions, check logs, execute scripts, etc. Pretty interesting for debugging workflows.

Copilot (VSCode): surprisingly improved recently. The big advantage is that premium requests are request-based instead of token-based.

Claude (Opus / Sonnet): still one of the strongest models when you need actual reasoning or complex code changes.








Saving tokens by using more tokens

This sounds weird, but sometimes the best way to save tokens is by using more tokens: just in the right places (not just one place but places).

If you force one expensive model to do everything, you'll burn a ridiculous amount of tokens.

Instead it's better to split tasks across tools.

For example:
Large tasks like: massive refactors, formatting big files, repetitive code changes
can burn tons of tokens on models like Claude or Cursor.
But Copilot charges per request, not per token.
So you can send huge prompts without worrying too much about token cost.

Using each tool for what it’s good at saves both time and money.
+ try generating prompts instead of just dumbing Your questions using broken english; if You dont understand what You wrote AI probably aint gonna understand it :)







About AI agents

There is a lot of hype right now about agentic coding workflows.

The idea is that an AI agent can build software by itself — writing code, running tests, fixing bugs, etc.
In reality, it's not quite there yet.
Agents are useful, but they still struggle with a few things.

First problem is context.
Most agents can't really see your whole codebase at once. Because of that they sometimes break things without realizing it.

Another issue is error loops.
Sometimes the agent makes a mistake and then keeps trying to fix its own mistake instead of realizing the approach is wrong.
Long tasks also cause problems because the agent slowly loses earlier context during long runs.

So fully autonomous development is still pretty unreliable.











Small safety tip
If your tool allows it, it's usually a good idea to disable automatic script execution.
Some AI tools will generate and run scripts automatically, and sometimes they do weird things.
It's safer to review what they're about to run first.












Final thought

People constantly argue about whether AI will replace developers.

Personally I think that debate is kind of pointless.

If AI becomes good enough to replace software engineers, then a lot of other knowledge jobs will disappear too.

So worrying about that doesn't really help.

Don't worry just learn how to use these tools well.

Developers who understand:
prompting
context engineering
AI-assisted workflows

will probably have a big advantage over developers who ignore these tools.
AI still makes mistakes, but when used properly it can massively speed up development.
